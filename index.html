Rewind: exactly-once execution for LLM agents

  • Crash-safe side effects for AI agents: an effect ledger for LangGraph that makes every real-world tool call (a refund, an email) happen exactly once, be safely skipped if the world changed, or be escalated to a human, even when the agent crashes and resumes.
  • A drop-in LangGraph tool node backed by a PostgreSQL effect ledger: an intent → dispatch → confirm state machine with step-derived idempotency keys, lookup-based recovery for ambiguous errors and timeouts, precondition re-validation after downtime, lease and fencing tokens against zombie workers, and saga compensation.
  • Cross-validated on real Stripe test mode (240 trials, 79 of 80 cells matched the simulated Stripe).
  • About 2,000 lines of source with 93 tests, including property-based tests, run in CI. The one remaining failure mode, a frozen worker waking before an email send, is documented.

NLP course project · USC · 2026

OmniLens: claim-level comparison of news coverage

Different outlets report the same event with different facts and framing. OmniLens compares their coverage at the level of individual claims, showing readers what sources agree on, what only one source adds, and where they contradict each other.

  • Built an end-to-end pipeline that takes two reports of the same event, extracts atomic claims with FENICE and an LLM, and labels each claim against the reference article as Shared, New or Conflicting.
  • Framed labeling as natural language inference (entailment, neutral, contradiction) and implemented NLI classifiers with DeBERTa-v3-large and ModernBERT-large, alongside a separate LLM-based classifier.
  • Created an annotated dataset of about 1,470 claims across 42 events, with inter-annotator agreement of Cohen’s κ 0.80–0.94 and event-level splits to prevent leakage.
  • Evaluated every method on the same held-out events with macro-F1, per-class precision and recall, and error analysis on the rare Conflicting class, reaching 96.4% accuracy, and built the pipeline into a working application.

Research project · IIT Dharwad · Jan 2023 – May 2024

Voice OTP: two-factor voice authentication

  • Designed a voice-based two-factor authentication system for remote logins, online banking and attendance tracking. A single spoken utterance is verified on two independent factors: speaker verification (who is speaking) and spoken-OTP recognition (what was said), and access is granted only when both pass.
  • Used ECAPA-TDNN x-vector embeddings (VoxCeleb) for speaker identification, against MFCC-VQ/GMM baselines, and a wav2vec 2.0 Conformer ASR model with a rule-based wrapper to decode the spoken OTP.
  • Built the DigitUtter-IITDH dataset (50 speakers, 1–4 digit OTPs) and used t-SNE analysis to justify in-domain fine-tuning, raising end-to-end accuracy from 78.92% to 93.21%.
  • Built the full system as a working end-to-end application and ran it live, profiling inference time and memory on a server, laptop CPU and Odroid edge board (0.068 s, 0.33 s, 1.74 s) for on-device deployment on mobile phones.

With Prof. S. R. Mahadeva Prasanna and Prof. Gayathri Ananthanarayanan.

Custom Search Engine for Government Websites

Government information is spread across many portals, and mainstream search engines often miss or bury it. We built a domain-specific search engine, in response to a NITI Aayog problem statement, that makes this information easy to find in one place.

  • Built a crawling and scraping pipeline in Python to collect pages and documents from government websites.
  • Cleaned and indexed the content in Elasticsearch for full-text retrieval and ranking, and applied NLP techniques to the content and queries to improve relevance over plain keyword matching.
  • Exposed search through a Flask REST API with a React front end, and used Elasticsearch to visualize the indexed data.
